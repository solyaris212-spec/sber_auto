# ИНСТРУКЦИЯ ПО ВВОДУ ДАННЫХ ДЛЯ ПРОГНОЗИРОВАНИЯ

## Общие сведения

Данная инструкция предназначена для сотрудников СберАвтоподписка, работающих с системой прогнозирования вероятности целевого действия пользователя на сайте.

Система анализирует данные о визитах пользователей и предсказывает, оставит ли посетитель заявку.

---

## РАЗДЕЛ 1. ИСТОЧНИКИ ТРАФИКА (UTM-МЕТКИ)

### 1.1. Источник трафика (utm_source)

**Что вводить:** Название поисковой системы, сайта или рекламной площадки

**Примеры:**
- yandex
- google
- vk
- facebook
- direct (прямой заход)
- auto.ru

**Правила:**
- Только строчные буквы
- Без пробелов
- Максимум 50 символов

---

### 1.2. Тип трафика (utm_medium)

**Что вводить:** Способ привлечения пользователя

**Допустимые значения:**
- organic (органический поиск)
- cpc (контекстная реклама)
- referral (переход с другого сайта)
- social (социальные сети)
- email (email-рассылка)
- none (не определен)

**Правила:**
- Использовать только значения из списка выше
- Только строчные буквы

---

### 1.3. Рекламная кампания (utm_campaign)

**Что вводить:** Название или идентификатор рекламной кампании

**Примеры:**
- auto_subscription_may
- brand_search_2024
- none (если не применимо)

**Правила:**
- Без пробелов (используйте нижнее подчеркивание)
- Только латинские буквы, цифры и символ подчеркивания
- Максимум 100 символов

---

### 1.4. Содержимое объявления (utm_adcontent)

**Что вводить:** Идентификатор конкретного объявления или креатива

**Примеры:**
- banner_blue_car
- text_ad_variant_a
- none

**Правила:**
- Без пробелов
- Максимум 100 символов

---

### 1.5. Ключевое слово (utm_keyword)

**Что вводить:** Поисковый запрос или ключевое слово

**Примеры:**
- автоподписка москва
- аренда авто долгосрочная
- none

**Правила:**
- Можно использовать пробелы
- Строчные буквы
- Максимум 200 символов

---

## РАЗДЕЛ 2. УСТРОЙСТВО ПОЛЬЗОВАТЕЛЯ

### 2.1. Тип устройства (device_category)

**Что вводить:** Категория устройства

**Допустимые значения:**
- desktop (настольный компьютер)
- mobile (мобильный телефон)
- tablet (планшет)

**Правила:**
- Только одно значение из списка
- Только строчные буквы

---

### 2.2. Операционная система (device_os)

**Что вводить:** Название ОС устройства

**Примеры:**
- Windows
- macOS
- Android
- iOS
- iPadOS
- Linux

**Правила:**
- С заглавной буквы
- Без указания версии
- Максимум 50 символов

---

### 2.3. Производитель устройства (device_brand)

**Что вводить:** Бренд устройства

**Примеры:**
- Apple
- Samsung
- Xiaomi
- Huawei
- Unknown (если неизвестно)

**Правила:**
- С заглавной буквы
- Максимум 50 символов

---

### 2.4. Браузер (device_browser)

**Что вводить:** Название браузера

**Примеры:**
- Chrome
- Safari
- Firefox
- Edge
- Opera
- Samsung Browser
- Chrome Mobile

**Правила:**
- С заглавной буквы
- Максимум 50 символов

---

### 2.5. Разрешение экрана (device_screen_resolution)

**Что вводить:** Разрешение экрана в пикселях

**Формат:** Ширина x Высота

**Примеры:**
- 1920x1080
- 1366x768
- 360x640
- 414x896

**Правила:**
- Только цифры и буква x (строчная)
- Без пробелов
- Без букв px
- Ширина указывается первой

---

## РАЗДЕЛ 3. ГЕОЛОКАЦИЯ

### 3.1. Страна (geo_country)

**Что вводить:** Название страны

**Примеры:**
- Russia
- Kazakhstan
- Belarus

**Правила:**
- С заглавной буквы
- Полное название страны
- Максимум 100 символов

---

### 3.2. Город (geo_city)

**Что вводить:** Название города

**Примеры:**
- Moscow
- Saint Petersburg
- Kazan
- Novosibirsk

**Правила:**
- С заглавной буквы
- Без сокращений
- Максимум 100 символов

---

## РАЗДЕЛ 4. ВРЕМЯ ВИЗИТА

### 4.1. Дата визита (visit_date)

**Что вводить:** Дата посещения сайта

**Формат:** ГГГГ-ММ-ДД

**Примеры:**
- 2024-05-15
- 2024-01-01
- 2023-12-31

**Правила:**
- Только цифры и дефисы
- Год из 4 цифр
- Месяц и день из 2 цифр (с нулем в начале при необходимости)
- Без пробелов

---

### 4.2. Время визита (visit_time)

**Что вводить:** Время посещения сайта

**Формат:** ЧЧ:ММ:СС

**Примеры:**
- 14:30:00
- 09:15:30
- 23:59:59

**Правила:**
- Только цифры и двоеточия
- 24-часовой формат
- Часы от 00 до 23
- Минуты и секунды от 00 до 59
- Без пробелов

---

## РАЗДЕЛ 5. ПОВЕДЕНИЕ ПОЛЬЗОВАТЕЛЯ

### 5.1. Номер визита (visit_number)

**Что вводить:** Порядковый номер визита пользователя на сайт

**Примеры:**
- 1 (первый визит)
- 3 (третий визит)
- 10 (десятый визит)

**Правила:**
- Только целые числа
- Минимум: 1
- Максимум: 1000
- Без десятичных дробей

---

### 5.2. Количество событий (hit_count)

**Что вводить:** Общее число действий пользователя в сессии

**Примеры:**
- 1 (просмотр одной страницы)
- 15 (средняя активность)
- 50 (высокая активность)

**Правила:**
- Только целые числа
- Минимум: 0
- Максимум: 1000
- Без десятичных дробей

---

### 5.3. Уникальные страницы (unique_pages)

**Что вводить:** Количество разных страниц, которые просмотрел пользователь

**Примеры:**
- 1 (одна страница)
- 5 (пять разных страниц)
- 12 (двенадцать страниц)

**Правила:**
- Только целые числа
- Минимум: 0
- Максимум: 100
- Не может быть больше hit_count

---

### 5.4. Количество событий с действием (event_count)

**Что вводить:** Число событий с зафиксированным event_action

**Примеры:**
- 0 (нет действий)
- 3 (три действия)
- 10 (десять действий)

**Правила:**
- Только целые числа
- Минимум: 0
- Максимум: 100
- Не может быть больше hit_count

---

### 5.5. Среднее время между событиями (avg_time_between_hits)

**Что вводить:** Среднее время в секундах между действиями пользователя

**Примеры:**
- 5.5 (пять с половиной секунд)
- 30.0 (тридцать секунд)
- 120.5 (две минуты)

**Правила:**
- Число с плавающей точкой
- Минимум: 0.0
- Максимум: 3600.0 (один час)
- Можно использовать точку для десятичных дробей
- Без единиц измерения

---

## РАЗДЕЛ 6. ФЛАГИ СОБЫТИЙ

Для каждого флага события вводится:
- 0 (событие не происходило)
- 1 (событие происходило)

### 6.1. Просмотр карточки автомобиля (has_event_view_card)

**Что означает:** Пользователь просматривал карточку автомобиля

**Значения:**
- 0 — не просматривал
- 1 — просматривал

---

### 6.2. Просмотр новой карточки (has_event_view_new_card)

**Что означает:** Пользователь просматривал новую карточку автомобиля

**Значения:**
- 0 — не просматривал
- 1 — просматривал

---

### 6.3. Лендинг подписки (has_event_sub_landing)

**Что означает:** Пользователь посещал лендинг услуги автоподписки

**Значения:**
- 0 — не посещал
- 1 — посещал

---

### 6.4. Переход в карточку (has_event_go_to_car_card)

**Что означает:** Пользователь переходил в карточку автомобиля

**Значения:**
- 0 — не переходил
- 1 — переходил

---

### 6.5. Просмотр списка автомобилей (has_event_sub_view_cars_click)

**Что означает:** Пользователь нажимал на просмотр списка автомобилей

**Значения:**
- 0 — не нажимал
- 1 — нажимал

---

## РАЗДЕЛ 7. ПРОВЕРКА ДАННЫХ ПЕРЕД ОТПРАВКОЙ

### Контрольный список:

1. Все обязательные поля заполнены
2. Форматы дат и времени соблюдены (ГГГГ-ММ-ДД, ЧЧ:ММ:СС)
3. Разрешение экрана в формате ШиринаxВысота (без пробелов)
4. Числовые значения в допустимых диапазонах
5. Флаги событий содержат только 0 или 1
6. Нет специальных символов в текстовых полях (кроме разрешенных)
7. Все значения введены строчными или заглавными буквами согласно правилам

### Частые ошибки:

**НЕПРАВИЛЬНО:**
- visit_date: 15.05.2024 (неверный формат разделителей)
- device_screen_resolution: 1920 х 1080 (пробелы и русская х)
- visit_number: 0 (минимальное значение 1)
- has_event_view_card: yes (только 0 или 1)
- utm_medium: Organic (должно быть строчными: organic)

**ПРАВИЛЬНО:**
- visit_date: 2024-05-15
- device_screen_resolution: 1920x1080
- visit_number: 1
- has_event_view_card: 1
- utm_medium: organic

## РАЗДЕЛ 9. ПОЛУЧЕНИЕ РЕЗУЛЬТАТА

После ввода всех данных система возвращает:

1. **probability** — вероятность целевого действия (от 0.0 до 1.0)
   - Пример: 0.7834 (78.34%)

2. **prediction** — бинарное предсказание
   - 0 — маловероятно, что пользователь оставит заявку
   - 1 — вероятно, что пользователь оставит заявку

3. **threshold** — порог классификации (фиксированное значение)

4. **latency_ms** — время обработки запроса в миллисекундах
